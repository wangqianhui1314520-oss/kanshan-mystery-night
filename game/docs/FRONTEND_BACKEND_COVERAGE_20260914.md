# 前后端功能覆盖审计（2026-09-14）

## 已落地并已接线

- **剧本与幕次**：`stage_changed`、`act_transition`、`case_intro`、难度设置、行动力同步（`ap_sync`）已进入 `store.js`，第二幕圆桌与第三幕指控阶段均可显示服务端状态。
- **记忆系统**：前端通过当前 WebSocket 玩家身份调用 `skill:memory_read`，服务端只返回该 NPC 已解锁版本；修复、拼图提交均走引擎校验，拼图消耗服务端篡改点。
- **舆论与竞标**：热榜竞标已改为真实 `bid_headline` 参数（帖子、金额、AP），服务端即时结算并返回 `headline_result`；热度侦察显示服务端 `heat_report`。
- **诊室开导**：前端发送 `target/card`，兼容服务端 `matched/transcript_hint` 返回，结果会更新 NPC 状态与聊天提示。
- **案件与证据**：搜证、证据合成、缺陷进度、Boss 就绪、投票待机等事件已接入状态层；在线模式下合成结果以服务端为准。
- **社交玩法**：NPC 私聊、公开发言、席位过滤、消息去重和真实引擎错误提示已接线。

## 后端已有、前端仍是局部或演示实现

1. **暗拍照片**：后端 `stealth_photo_result` 会返回照片对象，前端已有照片墙；但照片归属仍需按玩家身份隔离，`share_photo` 尚未有对应服务端动作路由，当前按钮只适用于本地演示协议。
2. **交叉验证（cross_check）**：`bag.js/store.js` 仍在本地生成真假判断和弹幕，未调用服务端裁决。
3. **多人竞标**：当前 `bid_headline` 是一次提交立即结算，未展示完整竞价轮次、倒计时、并发出价和观众回放。
4. **成就审计**：后端会发 `achievements_checked`（内部审计事件）；前端只展示最终成就卡，未提供审计明细面板。
5. **房间生命周期事件**：`npc_pending`、`player_rejoined`、`spectator_joined`、`rt_flow_error` 等事件主要用于运维/连接态，尚未单独做可视化状态。
6. **反诈、连麦、陈词、锤票、档案认领**：前端有交互组件，但部分动作仍走 mock/本地裁决；接入真实引擎时需逐项核对路由和返回事件。

## 第二幕/第三幕创新设计状态

`ACT2_ACT3_OPTIMIZATION.md` 中的记忆对质、阵营动态目标、证据公开/私藏/打包、联盟与六类结局目前是设计提案，尚未作为后端规则和前端流程发布。现有第二幕圆桌、第三幕指控已可运行，新增设计需要先冻结协议再实现。
