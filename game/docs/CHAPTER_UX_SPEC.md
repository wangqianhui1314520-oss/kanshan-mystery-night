# 章节独占式 UX 规格（V5）：机制归属总表 + 章节舞台

> 用户定案：UI 只显示当前章节（其他章机制彻底不在界面上），章节结束点击「进入下一章」才推进；机制归属彻底理清（全程公用 vs 章节私有）。
> 三幕叙事不变；本章基于已实现的 stages/actSet 门控重构呈现层。

## 一、机制归属总表（权威版）

### 1.1 全程公用机制（每章都在，跨章累积）

| 机制 | 说明 | 门控 |
|---|---|---|
| 对话（圆桌+私聊） | 与 DM/嫌疑人交流，大圆桌舞台常驻 | 全程 |
| 弹幕押注 | 每轮圆桌前押"最可疑的人"，赞数计分 | 每轮 |
| 系统抽风彩蛋 | DM 横幅抽风（【已打码】/错误惩罚） | 每幕 ≤2 次 |
| 破绽收集 | 看山的 5 处破绽散布三章，收集跨章累积 | 按线索条件 |
| 行动点经济 | 每轮 3AP，所有动作的货币 | 每轮重置 |
| 跨章资源栏 | 行动点/热度/破绽/知识卡/碎片/侦探证 常驻顶栏 | 全程常驻 |
| 成就/侦探证 | 元系统，跨章结算 | 全程 |

### 1.3 终局结算层（全章结束后的结算页）

指认投票（≥2 证据卡；破绽 5/5 →「指认 DM」）→ 结局矩阵 → 心晴诊室 → 侦探报告/成就/分享卡 → 署名页。

### 1.4 跨章资源与触发规则

- **知识卡**：章一抽取（收集），章二消费（开导弹药）——跨章资源；
- **篡改点**：章二产出，章节拼图消耗——章内闭环；
- **破绽**：三章各埋（1/2/2 分布），跨章累积；
- **热度**：章三主战场，前两章仅小波动；
- **行动点**：每章重置（章配额），不跨章。

## 二、章节独占式 UI 规格

1. **当前章独占全屏**：每章一张"章节舞台"（章名+主题色+本章机制入口），其他章的机制入口彻底不在 DOM 中（非灰态，是移除）；
2. **跨章资源栏**：顶部 30px 细条常驻（行动点/热度/破绽/知识卡/碎片/侦探证）——玩家唯一的全局视野；
3. **章末结算页**：本章结束条件满足 → 底部升起绿色「进入下一章 ▸」大按钮+本章收获结算；未满足 → 按钮灰态+缺口提示（"还差 1 个篡改点"）；
4. **章首前情提要**：进入新章先弹"前情提要"面板（上一章 200 字摘要+关键收获）——消费跨幕记忆摘要 memory_doc；
5. **本章机制入口**：只渲染本章机制按钮（1.2 表），公用机制（对话/押注）常驻；
6. **章节主题色**：章一知乎蓝 / 章二紫 / 章三红热 / 终局绿——按钮/边框/背景光随章切换。

## 三、实现要点

- driver 已有 stage 推进与章末条件（advance 门控），E 侧改为章节舞台视图：`S.act` 驱动当前章舞台渲染，`S.actCleared` 驱动「进入下一章」按钮；
- nav 侧栏取消，改为章内底部动作条（本章机制入口）+ 顶部跨章资源栏；
- 章末「进入下一章」→ 触发 advance（引擎门控仍是最终裁决）→ 转场插画 → 新章舞台；
- 归属：E（视图重构）+ G3 driver（章末条件事件 actCleared）+ G4（前情提要文案消费 memory_doc）。
