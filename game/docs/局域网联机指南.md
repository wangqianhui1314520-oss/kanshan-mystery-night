# 局域网多人联机指南 · 求真档案局

> 目标：同一个 WiFi / 路由器下的朋友，打开一个链接或输入 6 位房间码，就能真正加入你的房间一起玩。
> 本指南配合已完成的联机修复（房间码映射、独立玩家身份、真入席、分享链接）使用。

---

## 一、房主：启动服务（关键：监听 0.0.0.0）

在 `game/` 目录下执行：

```bash
pip install -r requirements.txt
python run.py
```

`run.py` 已配置监听 `0.0.0.0`（所有网卡），局域网内其他电脑才连得进来。
默认端口 `8899`，可用环境变量改：`PORT=9000 python run.py`。

> ⚠️ 不要用 `--host 127.0.0.1` 启动，那样只有你自己这台电脑能连。

启动成功后你自己先用浏览器打开：`http://localhost:8899`

---

## 二、房主：查出你的局域网 IP

朋友需要连的是你电脑的**内网 IP**，不是 `localhost`。

- **Windows**：命令行执行 `ipconfig`，找 “IPv4 地址”，形如 `192.168.x.x` 或 `10.x.x.x`
- **Mac/Linux**：执行 `ifconfig` 或 `ip addr`

好消息：**游戏已内置自动探测**。房主创建房间后，界面会直接显示形如
`http://192.168.1.23:8899/?room=235719` 的**分享链接**和“复制链接”按钮，
你不用手动查 IP，复制发给朋友即可（微信/QQ 群发都行）。**该链接只保证同一 WiFi/内网可达；跨网段或公网请使用已部署的 HTTPS 地址。**

---

## 三、房主：放行 Windows 防火墙（最容易漏的一步）

第一次运行 `python run.py` 时，Windows 会弹窗“是否允许 Python 访问网络”：
**务必勾选“专用网络”并点“允许访问”。**

如果当时手滑点了“取消/拒绝”，朋友会连不上。手动补救：
1. 控制面板 → Windows Defender 防火墙 → 允许应用通过防火墙
2. 找到 Python，勾选“专用”一列；或
3. 新建入站规则放行 TCP 端口 `8899`

---

## 四、朋友：两种加入方式（任选）

前提：朋友的电脑/手机连的是**和房主同一个 WiFi / 路由器**。

### 方式 A：点分享链接（最省事）
房主复制的链接（如 `http://192.168.1.23:8899/?room=235719`）发给朋友，
朋友在浏览器打开 → **自动进房**，直接选人开始。

### 方式 B：手动输房间码
1. 朋友浏览器打开 `http://192.168.1.23:8899`（房主的 IP:端口）
2. 首页选“房间模式（2-5 人）”
3. 输入房主给的 6 位房间码 → 点“加入房间”

---

## 五、玩起来

- 2-5 名真人各认领一个嫌疑人，空位由 AI 自动补齐；
- 每人行动点各算各的（每轮 3 点）；
- 有人掉线，AI 会无缝接管他的角色，不影响整局；
- 断线会自动重连（最多 6 次，指数退避）。

---

## 六、连不上？三步排查

按顺序排查，能快速定位卡在哪一层：

| 现象 | 排查 | 解决 |
|------|------|------|
| 朋友打不开页面 | 朋友 `ping 192.168.x.x`（房主 IP） | ping 不通 → 不在同一 WiFi，或房主防火墙拦了（回到第三节） |
| 页面能开、加入报错 | 看提示文字 | “房间不存在” → 房间码输错/房主没建房；“房间已满” → 换观战 |
| 加入后动作没同步 | 看右上角连接状态 | 显示“本地模式” → WS 没接通，检查 IP/端口/防火墙 |
| 全部正常但很卡 | 局域网带宽/设备性能 | 减少同时在线人数，或换有线网络 |

**快速自检命令**（朋友电脑上执行，替换成房主真实 IP）：
```bash
ping 192.168.1.23
```
- 通 → 网络层没问题，问题多半在防火墙或监听地址
- 不通 → 不在同一网段，或房主防火墙完全拦死

---

## 七、想让“不在同一 WiFi”的朋友也能玩？

局域网方案只覆盖同一路由器下。异地朋友需要**内网穿透**（本指南范围外，简述方向）：
- **虚拟局域网**（推荐，最简单）：房主和朋友都装 [Tailscale](https://tailscale.com/) 或 ZeroTier，
  组成虚拟内网后，用虚拟 IP 当作“局域网 IP”即可，游戏无需改动。
- **端口映射工具**：ngrok / Playit.gg / frp，把 `8899` 暴露到公网，朋友连公网地址。

> 涉及公网暴露有安全风险，仅在可信朋友间临时使用，玩完记得关掉。

## 附：本次联机修复改了什么（开发备忘）

| 文件 | 改动 |
|------|------|
| `server/main.py` | 新增房间码→session 映射 `ROOM_CODE_INDEX`；新增 `GET /api/room/{code}` 反查、`GET /api/lan-info` 局域网地址探测；建房时注册房间码（含防碰撞） |
| `frontend/js/net.js` | 每浏览器生成稳定唯一 `player_id`（localStorage）；`send()` 用真实 player_id 替代写死的 `player:1`；`Net.init` 支持传入 sessionId/playerId |
| `frontend/js/store.js` | `joinRoom` 改为“房间码反查 session → POST /join 真入席 → 用真实 session_id 连 WS”；`createRoom` 拉局域网地址生成分享链接；新增 `connectParty()` 重连真实房间通道 |
| `frontend/js/main.js` | 支持 `?room=6位码` 自动进房；party 界面显示分享链接 + 复制按钮 |

**修复前的三个致命 bug**：
1. 所有玩家动作都被当成 `player:1`（身份无法区分）；
2. `joinRoom` 只做 GET 校验、从不真正入席；
3. WS 误用 6 位房间码当 session_id，导致连不上。
