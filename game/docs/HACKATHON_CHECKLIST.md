## 1. 赛道匹配（最大得分/扣分项）

- 官方方向命中：解谜推理、AI NPC 对话、角色扮演、多结局均在赛道方向列表内；"欢乐"对应官方关键词"更轻盈、易传播"。
- **最大风险：与知乎社区生态契合度不足**。纯"AI 剧本杀"只是普通 AI 游戏；知乎内容必须成为玩法核心而非贴皮：
  - 盐言故事 API 拉真实故事 → 改编为剧本底座（保留作者署名，不得据为己作）；
  - 刘看山 IP 形象资源 → DM/主持人形象；
  - 知乎热榜/搜索 → 案件原型与"热梗"素材；
  - 直答 Agent → NPC 自由对话引擎。
- 产品说明（初审重点）必须逐条覆盖：核心创作思路、目标用户、核心体验路径、整体技术方案、使用了哪些知乎开放能力、与知乎生态契合点、对社区用户的实际价值。

## 2. 作品形态硬要求

- 最推荐 **网页/H5/HTML 线上应用**（评委点开链接直接体验）；App/小程序/桌面/插件/硬件亦可。
- **不接受纯 PPT/纯文档**；Demo 必须公网可访问、核心流程可实际操作。
- 关键设计：**评委单人可完整体验**。真人剧本杀 5-8 人开局在评审场景不可行——AI DM + AI NPC 扮演全部其他玩家，1 人开局即可走完 破冰→搜证→圆桌→指认→复盘。
- 提交字段：项目名称、赛道、介绍、线上 Demo 地址、产品说明/计划书、icon+封面；选交 GitHub/Gitee 仓库（工程规范加分）、演示视频（加分）。

## 3. API 使用纪律（官方 skill：zhihu-skill/zhihu/）

| 事项 | 结论 |
|---|---|
| 故事/知识内容接口 | 免鉴权，2026-09-12 实测可用（`api.zhihu.com/km-indep-home/hackathon/v2/...`） |
| 直答 Agent 等开放能力 | 需安装 zhihu-cli + Access Secret；限额按日计 → 必须做预生成缓存 + 节流 + 降级兜底 |
| 禁止行为 | 高频批量调用、刷屏灌水、垃圾内容推送 |
| 凭证安全 | App Key / Access Secret / OAuth Token 不得进前端、仓库、日志、截图、视频 |
| OAuth 知乎登录 | 回调地址必须与活动页登记值完全一致；登录数据关联最佳社区人气奖 |
| 算力/Token 补贴 | 建队后开放，每日 18:00 更新；宣讲口径约 500 美元 token/队 |

## 4. 48h 开发策略

- 现状：docs/ 与 content 模板骨架已就绪；`engine/`、`server/`、`frontend/` 代码未实现。
- 裁剪原则：**1 个剧本 × 5-6 角色 × 单一阵营机制**，优先保"单人对局全流程"跑通，再谈多房间/多人。
- 保持三条架构铁律：规则引擎与 AI 分离（AI 不裁决）、骨架+AI 填充（防剧情崩坏）、多 Agent 分工（DM/NPC/Judge/一致性守卫）。
- 部署：Demo 必须线上可访问（云端服务器或托管平台），提前验证公网连通与 HTTPS。
- 内容安全：自由对话接审核/过滤，违规由引擎拦截。

## 5. 提交前检查（官方原文要点）

1. Demo 公网可打开、核心流程可完成；
2. 项目名/介绍/赛道/封面/产品说明齐全；
3. 仓库与视频链接评委可访问；
4. OAuth 回调地址与登记一致；
5. 凭证未泄露在仓库/前端/日志/截图；
6. 接口失败、额度耗尽、空数据有真实降级提示；
7. 实际运行验证过，不把"代码完成"写成"线上可用"。
