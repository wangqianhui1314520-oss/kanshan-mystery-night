## 1. 方案 A「盐言迷局」—— 盐言故事 AI 改编本

- **电梯稿**：从盐言故事 API 拉一篇真实故事（保留作者署名），AI DM 将其改编为 5-6 人阵营推理本；玩家进入故事世界扮演角色，对话、搜证、指认，多结局由证据链达成度 + 投票决定。
- **玩法循环**：选本 → 角色分发 → 破冰自述 → 轮次搜证（线索池发放）→ 圆桌对质 → 指认投票 → 结局结算（真结局/反转结局/错杀结局）。
- **AI 原生点**：NPC 全 AI 扮演（人设锁定 + 秘密隐瞒）、DM 叙事动态生成、Judge Agent 给推理质量评分并影响结局分支。
- **复用现有工程**：直接落进 content/scenarios/template 结构，DM/NPC/Judge 三 Agent 即用。
- **风险与对策**：改编边界 → 界面常驻"改编自盐言故事《X》·作者 Y"署名；单本容量可控，48h 稳。

## 2. 方案 B「刘看山失踪夜」—— 看山 IP 欢乐阵营本（主推）

- **电梯稿**：刘看山在"知乎宇宙"里失踪了。6 名嫌疑人全是社区生态拟人角色：资深答主、盐言写手、热榜话题精、匿名吃瓜群众、AI 机器人、折叠区怨灵。好人民阵营"守护看山" vs 乱民阵营"节奏大师"，一局 20-30 分钟，综艺感拉满。
- **欢乐阵营机制**：轻量三件套——①身份暗置（每人一张隐藏阵营卡）②"热梗发言"轮次（AI 给每轮话题，发言可带节奏）③搜证拼图（线索凑齐才能发起指认）。
- **AI 原生点**：AI DM 控场（吐槽、节奏、规则仲裁）；AI NPC 自由对话（人设+秘密+立场）；**动态难度**——Judge Agent 实时评估玩家推理进度，新手局多放提示线索、老手局收窄证据模糊度。
- **知乎能力映射**：官方刘看山 IP 形象资源（DM 形象/美术成本最低）、直答 Agent、可选知乎 OAuth 登录。
- **为什么主推**：官方关键词"看山 IP 延展 + 轻巧、易传播 + 欢乐"全命中；内容完全自写（内容安全可控）；美术用官方素材（48h 最省）；单人评委体验路径最顺。
- **风险与对策**：IP 二创边界 → 用官方提供的 IP 形象资源、不做负面演绎；欢乐向要保推理成立 → truth.json 真相表预置锚定。

## 3. 方案 C「热榜悬案」—— 社区内容驱动的每日新案

- **电梯稿**：开局实时拉知乎热榜，AI 将 TOP 话题融合改写成一桩"悬案"底座（人工真相表锚定防崩坏），玩家搜证推理；每天案子都不一样，可重复传播。
- **AI 原生点**：AI 生成剧情（方向⑤原词命中）、动态难度、AI NPC。
- **风险与对策**：真实事件娱乐化的内容安全风险（敏感话题必须过滤/白名单）；纯 AI 生成案件质量不稳定 → "骨架+AI 填充"：真相表、线索池人工预置，热榜只做题材换皮。
- **48h 建议**：不单独做；作为 B 的"每日悬案模式"彩蛋（预生成 3-5 个案件库 + 热榜话题挂钩），时间富余才上线。

## 4. 方案 D「同好卧底局」—— 社交关系链阵营竞技

- **电梯稿**：知乎 OAuth 登录后，AI 读取公开关注/收藏生成个人"知乎人设卡"入局；真人 + AI 玩家混编同房，找出隐藏在其中的卧底。
- **命中**：方向④原词命中，社交传播潜力大（熟人拉熟人）。
- **风险与对策**：OAuth 回调地址审核与 48h 工期冲突最大；多人联机后端工作量翻倍；评委单人体验路径最弱。
- **48h 建议**：不单独做；降级为 B/A 里的"知乎账号登录"浅接入（登录数据关联最佳社区人气奖评判），好友邀请链接做"异步房间码"而非实时联机。

## 5. 首选推荐：B 主线 + A 融合 + C 彩蛋 + D 浅接入

| 层 | 取自 | 落地内容 |
|---|---|---|
| 主线玩法 | 方案 B | 看山 IP 欢乐阵营本，5-6 角色，1 人开局 AI 扮演全场 |
| 内容源 | 方案 A | "盐言写手"角色的作品 = 盐言 API 拉取的真实故事（署名改编），命中方向① |
| 扩展模式 | 方案 C | "每日悬案"入口（预生成案件库），命中方向⑤ AI 生成剧情 |
