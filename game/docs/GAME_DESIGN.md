# 游戏设计文档：AI原生大型剧本杀

> 目标：还原线下大型剧本杀的完整体验，由 AI 承担组织者（DM）、全部 NPC、搜证系统与推理裁判。
> 玩家不读大段剧本，而是"进入角色，自己演"。

## 一、核心体验循环

```
选择角色 → 阅读个人任务（目标） → 与 NPC/其他玩家对话 → 搜证 → 私聊/圆桌推理
   → 指认投票 → 复盘揭晓
```
每一轮循环都由 AI 动态生成内容，但"什么阶段能做什么、证据怎么算、结局怎么判"由规则引擎锁定。

## 二、剧本杀标准流程（AI 原生映射）

| 阶段 | 线下剧本杀 | AI 原生实现 | 引擎控制 |
|---|---|---|---|
| 0 选角 | 读本选角色 | 展示角色卡（人设/任务/秘密），AI 简述开场 | 角色唯一性校验 |
| 1 破冰 | 自我介绍、认识彼此 | 玩家自述 + AI NPC 介绍 + 场景描写 | 发言轮次控制 |
| 2 搜证 | 抽取线索卡 | 玩家指定地点/对象搜证，引擎按"搜索条件→线索池"发卡，AI 生成线索细节 | **证据链系统** |
| 3 圆桌 | 集体讨论、互相盘问 | 玩家与任意 NPC/玩家对话，AI NPC 按人设回答（会说谎、会隐瞒） | 对话上下文管理 |
| 4 私聊 | 私下交换信息 | 1v1 私聊室（AI NPC 或真人） | 会话隔离 |
| 5 指认 | 投票指认凶手 | 玩家提交指认（凶手+动机+手法），裁判 Agent 按证据链打分 | **裁决器** |
| 6 复盘 | DM 揭晓真相 | DM Agent 生成复盘叙事，展示真相表与玩家推理对比 | 真相表回放 |

## 三、大型剧本杀的特殊设计

### 3.1 角色系统（6-12 人）
- 每个角色 = 角色卡 JSON：公开信息（外貌/职业）+ 秘密（动机/罪行/真实身份）+ 任务目标 + 关系网
- **分层可见性**：玩家只看到自己的公开信息与任务；秘密对 AI 可见，NPC 只在被问到时选择性暴露
- NPC 角色（AI 扮演）数量 ≥ 玩家数量，保证对话密度

### 3.2 证据链系统（核心创新）
- 线索分三级：**公开线索**（圆桌可共享）/ **限定线索**（指定玩家独享）/ **隐藏线索**（需条件触发）
- 每条线索带：`内容、关联角色、关联真相节点、发放条件、是否可伪造`
- 矛盾检测：AI 证词与已有线索冲突时，一致性守卫拦截并要求 NPC 修正或玩家质疑

### 3.3 时间线与行动力
- 每个搜证/对话动作消耗行动力，防止无限刷证据
- 案发时间线：所有角色当晚的行动轨迹，NPC 叙述必须与 timeline.json 一致

### 3.4 多结局判定
- 真相达成度 0-100%：指认命中凶手 + 动机正确 + 手法正确 + 伏笔回收数
- 结局档位：完美还原（100%）/ 部分还原（60-99%）/ 指认错误（真相揭开但凶手逃脱）等

## 四、AI 分工与边界

| 职责 | 归属 | 禁止 |
|---|---|---|
| 场景/对话/证词生成 | NPC Agent、DM Agent | 生成"不存在的证据" |
| 规则解释、行动裁决 | 规则引擎 | AI 自由发挥 |
| 推理评分、结局判定 | 裁判 Agent + 裁决器 | 玩家说什么都对 |
| 角色言行一致性 | 一致性守卫 | 前后矛盾、OOC |
| 世界观知识供给 | 内容层 RAG | 无凭据编造设定 |

## 五、MVP 里程碑（黑客松 9.15 前）

- **M1（骨架）**：单剧本《雾城谜案》完整内容资产（4 玩家 + 2 AI NPC + 8 线索 + 真相表）
- **M2（流程）**：搜证→圆桌→指认→复盘 全流程可跑，规则引擎裁决
- **M3（AI 接入）**：NPC/DM 对话接入直答 Agent，角色卡 System Prompt 锁定
- **M4（交付）**：Web Demo 可在线游玩，产品计划书完成
