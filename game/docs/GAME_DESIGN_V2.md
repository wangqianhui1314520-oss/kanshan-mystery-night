# 游戏设计文档 V2：《求真档案局 · 看山失踪夜》

> 取代 V1 的单剧本 MVP 设计（V1 保留作流程规范参考）。
> 定位：欢乐阵营机制推理本（剧本杀）· AI 原生 · 单部作品三幕制
> 整合三个机制概念：看山 IP 阵营本 + 记忆碎片（记忆篡改） + 热搜疑云（舆论操纵）
> 更新时间：2026-09-12

## 一、统一世界观

**知乎都市宇宙**。「求真档案局」是专门处理"信息污染案件"的神秘机构，刘看山是档案局首席荣誉侦探（北极狐）。周五盘点夜 21:00，看山进档案室后失踪——现场留下被挖空的监控（21:07–21:15）、可被改写的记忆存证，和一场迅速冲上热搜的舆论风暴。

玩家是档案局连夜召集的"特聘侦探"，但其中混进了污染阵营的人。

**三章机制不是三个剧本，是一场对局的三幕**：评委一人一次玩完，就能看到全部 AI 亮点。

## 二、底层阵营机制（全程贯穿）

| 机制 | 设计 |
|---|---|
| 身份暗置 | 每人一张隐藏阵营卡：**求真阵营**（守护看山）vs **污染阵营**（篡改者/水军头子） |
| 轮次发言 | 每轮由 AI DM 抛出一个"知乎话题"，发言可带节奏；AI 生成欢乐弹幕实时吐槽 |
| 阵营技能 | 消耗行动力释放（见三幕机制联动） |
| 结局判定 | 指认投票 × 证据链达成度 → 多结局：完美还原 / 反转结局 / 污染胜利结局 |

## 三、三幕结构

### 第一幕「失踪夜」—— 阵营 + 搜证基础
- 6 名嫌疑人（社区生态拟人，欢乐向）被锁进档案局：资深答主、盐言写手、热榜话题精、匿名吃瓜群众、AI 机器人、折叠区怨灵。
- 机制：轮次搜证（线索池发放）+ 圆桌对质 + AI 弹幕吐槽。

### 第二幕「记忆碎片」—— 记忆篡改机制 ★
- 关键证人的记忆芯片被编辑：NPC 的关键记忆存在 **V1 / V2（部分 V3）多版本**。
- 玩家消耗行动力使用"**记忆修复**"解锁备份记忆 → **对比版本差异找出篡改点** = 核心证据链。
- AI 核心：NPC"记得的"随证据解锁**动态变化**（memory_state 注入 prompt；一致性守卫拦截记忆崩坏）。
- 内容源：剧情底座改编自盐言科幻故事（界面常驻作者署名）；世界观知识库用知乎知识接口（科技伦理主题）做 RAG。

### 第三幕「热搜疑云」—— 舆论操纵机制 ★
- 案件"冲上热搜"：对局内**热搜面板**每轮刷新 AI 生成帖子/热评，其中混入水军帖（假线索）。
- 阵营技能联动：
  - 污染阵营：**买热搜**（置顶假线索）、**水军控评**（淹没真线索）、带节奏发言；
  - 求真阵营：**记忆修复**（第二幕技能延续）、**官方辟谣**（降热度解真线索）、**举报水军**（需证据支持）。
- 热度值系统：热度越高真线索越难解锁，阵营博弈的杠杆。
- 真实知乎热榜：用于"**每日挑战**"模式（热榜话题挂钩案件彩蛋），主案预生成保内容安全。

### 与 V1 流程的映射
```
选角 → 破冰 → [第一幕:搜证+圆桌] → [第二幕:记忆对比] → [第三幕:舆论博弈] → 指认 → 复盘
        └── stage_machine 锁阶段 ──┴── memory_system ──┴── opinion_feed ──┴ resolver 裁决
```
新增引擎模块：`engine/memory_system.py`（多版本记忆/篡改点）、`engine/opinion_feed.py`（热度值/帖子刷新/水军逻辑）。AI 只做对话与叙事，阶段/线索/结局仍由规则引擎裁决（三铁律不变）。

## 四、API 接入方案（回答"要不要接 API"）

**结论：要接，且 API 是玩法的一部分，不是装饰。** 官方规则未写"强制接入"，但产品说明必须回答"使用了哪些知乎开放能力"，且赛道方向全部围绕知乎内容生态——实际必接。

| 层 | 能力 | 用途 | 鉴权 | 限额策略 |
|---|---|---|---|---|
| 内容层 | 盐言故事 API | 第二幕剧情底座（科幻 IP 改编，保留署名） | 免鉴权 | 开局拉取入库 |
| 内容层 | 知乎知识 API | 科技伦理知识库（第二幕 RAG） | 免鉴权 | 制作期预检索入库 |
| 能力层 | 热榜 API | "每日挑战"模式 | 需 Access Secret（zhihu-cli） | 约 100 次/日，缓存+开关降级 |
| 能力层 | 知乎搜索 | 案件原型/多立场素材 | 需 Access Secret | 制作期用，运行期不用 |
| 能力层 | 直答 Agent | 档案局智能助手、每日案件导读等**低频高光**场景 | 需 Access Secret | 约 100 次/日，预生成缓存 |
| 登录 | OAuth | 知乎账号登录（关联最佳社区人气奖） | 页面登记回调地址 | 浅接入 |

**关键纪律**：
1. NPC 主力对话**不走直答 Agent**（限额扛不住对话密度），走自建 LLM + 全量预生成缓存；直答只做点睛场景。
2. 所有凭证（Access Secret/App Key/Token）只存后端，不进前端/仓库/日志/截图。
3. 实时热榜内容不可控 → 主案预生成，热榜仅做"每日挑战"彩蛋并加话题白名单过滤。

## 五、48h 里程碑

| 里程碑 | 内容 | 裁剪优先级 |
|---|---|---|
| M1 | 引擎 + 第一幕完整可玩（阵营+搜证+指认+复盘） | 不可裁 |
| M2 | 记忆碎片机制（V1/V2 预生成 + 修复解锁 + 动态切换） | 次高 |
| M3 | 热搜面板（预生成帖子池 + 每轮刷新 + 阵营技能） | 次高 |
| M4 | 热榜"每日挑战" + OAuth 登录 | **可裁** |
| M5 | 公网部署 + 产品说明 + 演示视频 + 提交 | 不可裁 |

内容工作量（可由 AI 批量预生成）：6 角色卡 × 多版本记忆、真相表、线索池 12-16 条、热搜帖池 24-30 条、弹幕池、三幕剧本文本。

## 六、产品说明对位（初审考核项）

| 考核项 | 本作回答 |
|---|---|
| 核心创作思路 | 信息可被篡改时代的"求真"隐喻，欢乐外壳 + 推理内核 |
| 目标用户 | 剧本杀爱好者、知乎社区用户、AI 游戏尝鲜者 |
| 核心体验路径 | 单人开局 → AI DM 带三幕 → 多结局复盘 |
| 技术方案 | 规则引擎与 AI 分离 + 四 Agent（DM/NPC/Judge/守卫）+ 多版本记忆引擎 |
| 使用的知乎开放能力 | 盐言故事、知乎知识、热榜、搜索、直答、OAuth（上表） |
| 生态契合点 | 看山 IP、社区生态拟人角色、"热搜带节奏"即知乎真实场景 |
| 社区价值 | 在娱乐中体验"识别信息操纵"，呼应知乎求真社区文化 |
